# 5. Non-Contiguous Allocation & Paging

## What is Non-Contiguous Allocation?
In **Non-Contiguous Allocation**, a process's memory is divided into smaller chunks that can be placed in **any available, non-adjacent physical frames** across RAM.

- **Primary Benefit:** Completely eliminates **External Fragmentation**!

---

## What is Paging?
- **Paging** is a memory management scheme that divides:
  1. **Logical Memory** into fixed-size blocks called **Pages**.
  2. **Physical Memory (RAM)** into fixed-size blocks of the exact same size called **Page Frames (Frames)**.
- **Rule:** $\text{Page Size} == \text{Frame Size}$ (Typically $4\text{ KB} = 4096\text{ bytes} = 2^{12}\text{ bytes}$).

---

## Logical Address Translation in Paging

A Logical Address generated by CPU is split into two binary parts:

```
+--------------------------+--------------------------+
|     Page Number (p)      |     Page Offset (d)      |
+--------------------------+--------------------------+
  (Index into Page Table)      (Exact byte in the page)
```

$$\text{If Logical Address space is } 2^m \text{ bytes and Page Size is } 2^n \text{ bytes:}$$
- **Page Offset ($d$):** $n$ bits.
- **Page Number ($p$):** $m - n$ bits.

---

## The Hardware Translation Pipeline

```
  Logical Address: (p, d)
        |
        v
  [ PAGE TABLE ]  -->  Look up Frame Number (f) for Page (p)
        |
        v
  Physical Address: (f, d)  --->  Access RAM Byte!
```

$$\text{Physical Address} = (\text{Frame Number } f \times \text{Page Size}) + \text{Offset } d$$

---

## Paging Fragmentation Analysis
- **External Fragmentation:** **0% (Zero)** because any free frame can be assigned to any page.
- **Internal Fragmentation:** At most in the **last page of a process** (average $\text{Page Size} / 2$, worst case $\text{Page Size} - 1\text{ byte}$).
